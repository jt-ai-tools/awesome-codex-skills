# 開發者成長分析 (Developer Growth Analysis)

此技能透過分析您的 Codex 聊天互動，識別展現優勢與成長空間的模式，為您最近的編碼工作提供個性化回饋。

## 何時使用此技能

當您想要執行以下操作時，請使用此技能：
- 從最近的工作中了解您的開發模式與習慣
- 識別特定的技術差距或重複出現的挑戰
- 發現哪些主題能從深入研究中獲益
- 獲取針對您實際工作模式量身定制的精選學習資源
- 追蹤近期專案中的改進領域
- 尋找直接針對您正在開發的技能的高品質文章

此技能非常適合想要獲得結構化成長回饋（無需等待程式碼審查），且偏好從自身工作歷史中獲取數據驅動洞察的開發者。

## 此技能的功能

此技能對您的開發工作執行六個步驟的分析：

1. **讀取聊天紀錄**：存取您過去 24-48 小時內的本地 Codex 聊天紀錄，以了解您一直以來的工作內容。

2. **識別開發模式**：分析您正在解決的問題類型、使用的技術、遇到的挑戰，以及您處理不同任務的方法。

3. **偵測改進領域**：識別暗示技能差距、重複困境、低效方法或您可能從更深入知識中獲益的模式。

4. **生成個性化報告**：建立一份綜合報告，展示您的工作總結、識別出的改進領域以及具體的成長建議。

5. **尋找學習資源**：利用 HackerNews 整理與您的改進領域直接相關的高品質文章與討論，為您提供針對實際開發工作量身定制的閱讀清單。

6. **發送至您的 Slack 私訊**：自動將完整報告發送至您自己的 Slack 私訊，以便您隨時隨地參考。

## 如何使用

要求 Codex 分析您最近的編碼工作：

```
從我最近的聊天紀錄分析我的開發者成長
```

或者針對特定時間段：

```
分析我今天的工作並建議待改進領域
```

此技能將生成一份格式化的報告，包含：
- 您最近的工作概覽
- 識別出的關鍵改進領域
- 針對每個領域的具體建議
- 來自 HackerNews 的精選學習資源
- 您可以專注執行的行動項目

## 指令說明

當使用者請求分析其開發者成長或最近工作的編碼模式時：

1. **存取聊天紀錄**

   讀取 `$CODEX_HOME/history.jsonl`（預設為 `~/.codex/history.jsonl`）中的聊天紀錄。此檔案為 JSONL 格式，每行包含：
   - `display`：使用者的訊息/請求
   - `project`：正在進行的專案
   - `timestamp`：Unix 時間戳記（毫秒）
   - `pastedContents`：任何貼上的程式碼或內容

   根據當前時間戳記篩選過去 24-48 小時內的條目。

2. **分析工作模式**

   從篩選後的聊天紀錄中擷取並分析以下內容：
   - **專案與領域**：使用者正在進行哪些類型的專案？（例如：後端、前端、DevOps、數據分析等）
   - **使用的技術**：對話中出現了哪些語言、框架與工具？
   - **問題類型**：正在解決哪些類別的問題？（例如：效能優化、偵錯、功能實作、重構、安裝/配置）
   - **遇到的挑戰**：使用者在哪些問題上掙扎？尋找以下跡象：
     - 針對相似主題重複提問
     - 需要多次嘗試才能解決的問題
     - 顯示知識差距的提問
     - 複雜的架構決策
   - **處理方法模式**：使用者如何解決問題？（例如：有系統的、探索性的、實驗性的）

3. **識別改進領域**

   根據分析，識別 3-5 個使用者可以改進的特定領域。這些領域應具備：
   - **具體性**（而非像「提升編碼技能」這樣模糊）
   - **有證據支持**（立足於實際聊天紀錄）
   - **可執行性**（可以執行的實際改進措施）
   - **優先級**（最有影響力的排在前面）

   良好的改進領域範例：
   - 「進階 TypeScript 模式（泛型、工具型別、型別守衛）——您在 [特定專案] 中遇到了型別安全方面的困難」
   - 「錯誤處理與驗證——我注意到您修復了幾個與遺漏 null 檢查相關的 Bug」
   - 「Async/await 模式——您最近的工作顯示出一些競態條件 (Race conditions) 與時序問題」
   - 「資料庫查詢優化——您多次重寫了相同的查詢」

4. **生成報告**

   建立具備以下結構的綜合報告：

   ```markdown
   # 您的開發者成長報告 (Developer Growth Report)

   **報告期間**：[昨天 / 今天 / [自訂日期範圍]]
   **最後更新**：[當前日期與時間]

   ## 工作總結 (Work Summary)

   [使用 2-3 個段落總結使用者的工作內容、參與的專案、使用的技術以及整體關注領域]

   範例：
   「在過去 24 小時內，您主要專注於三個不同專案的後端開發。您的工作涉及 TypeScript、React 和部署基礎設施。您處理了功能實作、偵錯和架構決策，特別關注 API 設計與資料庫優化。」

   ## 改進領域 (依優先級排序)

   ### 1. [領域名稱]

   **為什麼這很重要**：[解釋為什麼這項技能對使用者的工作很重要]

   **我的觀察**：[來自聊天紀錄的具體證據，顯示此項差距]

   **建議**：[改進此領域的具體步驟]

   **技能提升所需時間 (Time to Skill Up)**：[簡要估計所需的努力程度]

   ---

   [針對另外 2-4 個領域重複上述內容]

   ## 觀察到的優勢

   [使用 2-3 個列點強調您做得好的地方——即應繼續保持的部分]

   ## 行動項目 (Action Items)

   優先順序：
   1. [源自最高優先級改進領域的行動項目]
   2. [源自下一個領域的行動項目]
   3. [源自下一個領域的行動項目]

   ## 學習資源

   [將在下一步中填入]
   ```

5. **搜尋學習資源**

   使用 Rube MCP 針對每個改進領域在 HackerNews 上搜尋相關文章：

   - 為每個改進領域構建針對高品質資源的搜尋查詢
   - 使用 RUBE_SEARCH_TOOLS 搜尋 HackerNews，查詢內容如：
     - "Learn [Technology/Pattern] best practices" (學習 [技術/模式] 最佳實踐)
     - "[Technology] advanced patterns and techniques" ([技術] 進階模式與技巧)
     - "Debugging [specific problem type] in [language]" (在 [語言] 中偵錯 [特定問題類型])
   - 優先選擇參與度高（評論多、推文數多）的貼文
   - 針對每個領域，包含 2-3 篇最相關的文章，並附帶：
     - 文章標題
     - 發布日期
     - 為什麼相關的簡要描述
     - 文章連結

   將此章節新增至報告中：

   ```markdown
   ## 精選學習資源

   ### 針對：[改進領域]

   1. **[文章標題]** - [日期]
      [涵蓋內容的描述，以及為什麼與您的改進領域相關]
      [連結]

   2. **[文章標題]** - [日期]
      [描述]
      [連結]

   [針對其他改進領域重複上述內容]
   ```

6. **呈現完整報告**

   以整潔、易讀的格式交付報告，以便使用者可以：
   - 快速掃描關鍵重點
   - 用於有針對性的學習規劃
   - 在接下來的一週工作中參考改進建議
   - 如果想要外部回饋，可以與導師分享

7. **發送報告至 Slack 私訊**

   使用 Rube MCP 將完整報告發送至使用者自己的 Slack 私訊：

   - 透過 RUBE_SEARCH_TOOLS 檢查 Slack 連接是否作用中
   - 如果未連接，使用 RUBE_MANAGE_CONNECTIONS 啟動 Slack 授權
   - 使用 RUBE_MULTI_EXECUTE_TOOL 將報告作為格式化訊息發送：
     - 將報告標題與期間作為第一則訊息發送
     - 將報告拆分為邏輯章節（總結、改進、優勢、行動、資源）
     - 將每個章節格式化為具備良好結構且帶有適當 Markdown 的 Slack 訊息
     - 包含學習資源的可點擊連結
   - 在 CLI 輸出中確認已送達

   這確保了使用者能在定期查看的地方獲得報告，並能在整週工作中隨時參考。

## 範例用法

### 輸入

```
從我最近的聊天紀錄分析我的開發者成長
```

### 輸出範例

```markdown
# 您的開發者成長報告

**報告期間**：2024 年 11 月 9-10 日
**最後更新**：2024 年 11 月 10 日, 9:15 PM UTC

## 工作總結

在過去兩天中，您專注於後端基礎設施與 API 開發。您的主要專案是一個開源展示應用程式，您在連接管理、UI 改進與部署配置方面取得了重大進展。您使用了 TypeScript、React 與 Node.js，處理了從資料安全到響應式設計的各種挑戰。您的工作顯示了在實作功能與處理技術債之間取得了平衡。

## 改進領域 (依優先級排序)

### 1. 進階 TypeScript 模式與型別安全

**為什麼這很重要**：TypeScript 是您工作的核心，利用其進階功能（泛型、工具型別、條件型別、型別守衛）可以顯著提高程式碼的可靠性並減少執行階段錯誤。更好的型別安全能在編譯時而非生產環境中捕捉 Bug。

**我的觀察**：在您最近的聊天中，您正在處理連接資料結構，並在正確定義認證配置型別時遇到了幾次困難。您還必須針對不同連接狀態迭代聯集型別。現在是一個更有效地使用辨別聯集 (Discriminated unions) 與型別守衛 (Type guards) 的機會。

**建議**：研究 TypeScript 的進階型別系統，特別是工具型別 (Omit, Pick, Record)、條件型別與辨別聯集。將這些模式應用於您的連接配置處理與認證狀態管理。

**技能提升所需時間**：5-8 小時的專注學習與練習

### 2. UI 中的安全資料處理與資訊隱藏

**為什麼這很重要**：您識別並修復了一個安全隱患，即敏感的連接資料被顯示在主控台中。防止資訊洩漏對於處理使用者憑證與 API 金鑰的應用程式至關重要。良好的實踐可以預防安全事件並避免損害使用者信任。

**我的觀察**：您發現「您的應用程式」頁面顯示了包含認證配置在內的完整連接資料。這顯示了良好的安全直覺，下一步是在處理敏感資訊時將其納入預設思維。

**建議**：審查前端應用程式處理敏感資料的安全最佳實踐。建立可用於在顯示前過濾/遮罩敏感資訊的可重複使用模式。考慮實作一個明確白名單化可在 UI 中顯示內容的安全資料層。

**技能提升所需時間**：3-4 小時

### 3. 元件架構與響應式 UI 模式

**為什麼這很重要**：您正在設計需要跨不同螢幕尺寸與使用者互動的 UI。強大的元件架構使建構複雜 UI 變得更容易，且能減少 Bug 並提高可維護性。

**我的觀察**：您參與了「市集」UI 的工作，根據設計圖重新製作。您還識別並修復了內容超出容器的滾動問題。現在是一個加深對佈局容納 (Layout containment) 與響應式設計模式理解的機會。

**建議**：研究 React 元件組合模式與 CSS 佈局最佳實踐（特別是 flexbox 與 grid）。專注於容器查詢與防止溢出問題的響應式模式。研究元件組合庫與設計系統方法。

**技能提升所需時間**：6-10 小時（視深度而定）

## 觀察到的優勢

- **安全意識**：您主動在資料洩漏演變成問題之前就識別出它
- **迭代精煉**：您有系統地處理 UI 需求，提出澄清性問題並改進設計
- **全端開發能力**：您能自在地處理後端 API、前端 UI 與部署問題
- **問題解決方法**：您能將複雜任務拆解為可管理的步驟

## 行動項目

優先順序：
1. 花 1-2 小時學習 TypeScript 工具型別與辨別聯集；並應用於您的連接資料結構
2. 為您的專案文件化安全模式（哪些資料可以安全顯示，過濾/遮罩函數為何）
3. 閱讀一篇關於進階 React 模式的文章，並將一種模式應用於您目前的 UI 工作
4. 為未來的 PR 建立一個專注於型別安全與資料安全的程式碼審查檢查清單
```

## 提示與最佳實踐

- 每週執行一次此分析，以追蹤您的改進軌跡。
- 一次挑選一個改進領域，專注於該領域幾天後再移動到下一個。
- 將學習資源作為學習指南；研讀推薦的材料並練習應用這些模式。
- 在專注於某個領域一週後重新檢視此報告，觀察您的工作模式發生了什麼變化。
- 學習資源是針對您的實際工作刻意挑選的，而非通用的主題，因此它們會與您正在建構的內容高度相關。

## 準確性與品質維護

此技能：
- 從帶有時間戳記的聊天紀錄中分析您實際的工作模式。
- 產生立足於真實專案、有證據支持的建議。
- 整理直接解決您識別出的差距的學習資源。
- 專注於可執行的改進，而非模糊的回饋。
- 根據複雜程度提供具體的時間估計。
- 優先處理對您的開發速度最有影響力的領域。
