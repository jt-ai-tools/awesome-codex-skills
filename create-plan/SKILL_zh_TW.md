# 建立計畫 (Create Plan)

## 目標

將使用者的提示詞 (Prompt) 轉化為一個**單一且可執行**的計畫，並在助理的最終訊息中交付。

## 極簡工作流程

在整個工作流程中，請以「唯讀模式」運作。請勿寫入或更新檔案。

1. **快速掃描上下文**
   - 閱讀 `README.md` 和任何顯眼的文件（如 `docs/`, `CONTRIBUTING.md`, `ARCHITECTURE.md`）。
   - 略讀相關檔案（最有可能被改動的部分）。
   - 識別限制條件（語言、框架、CI/測試指令、部署形式）。

2. **僅在遇到阻礙時進行追問**
   - **最多提出 1–2 個問題**。
   - 僅在沒有答案就無法負責任地制定計畫時才提問；優先採用多選題形式。
   - 如果不確定但未受阻，請做出合理的假設並繼續。

3. **使用下方模板建立計畫**
   - 開頭使用 **1 段短文** 描述意圖與方法。
   - 簡要標註哪些部分在 **範圍內 (In scope)**，哪些在 **範圍外 (Out of scope)**。
   - 接著提供一個 **行動項目檢查清單 (Action items)**（預設 6–10 項）。
      - 每個清單項應為具體行動，並在有幫助時提及檔案/指令。
      - **確保項目是原子級 (Atomic) 且有序的**：調查 (Discovery) → 變更 (Changes) → 測試 (Tests) → 上線 (Rollout)。
      - **動詞開頭**：例如「新增...」、「重構...」、「驗證...」、「發布...」。
   - 在適用時，至少包含一項 **測試/驗證** 以及一項關於 **邊緣案例/風險** 的項目。
   - 如果存在未知事項，請包含一個極短的 **待解決問題 (Open questions)** 章節（最多 3 項）。

4. **不要在計畫前加上後設說明；請嚴格按照模板輸出計畫內容**

## 計畫模板（請嚴格遵循）

```markdown
# 計畫 (Plan)

<1–3 句話：說明我們要執行的任務、原因以及高層級的方法。>

## 範圍 (Scope)
- 範圍內 (In)：
- 範圍外 (Out)：

## 行動項目 (Action items)
[ ] <步驟 1>
[ ] <步驟 2>
[ ] <步驟 3>
[ ] <步驟 4>
[ ] <步驟 5>
[ ] <步驟 6>

## 待解決問題 (Open questions)
- <問題 1>
- <問題 2>
- <問題 3>
```

## 檢查清單項目指南
良好的清單項目範例：
- 指向可能的檔案/模組：`src/...`, `app/...`, `services/...`
- 命名具體的驗證方式：「執行 `npm test`」、「為 X 新增單元測試」
- 在相關時包含安全上線方案：功能開關 (Feature Flag)、遷移計畫、回滾註記 (Rollback note)

避免：
- 模糊的步驟（如「處理後端」、「處理認證」）
- 過多微小的碎步
- 撰寫程式碼片段（保持計畫與實作無關 [Implementation-agnostic]）
