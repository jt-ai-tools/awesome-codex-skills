# 變更日誌生成器 (Changelog Generator)

此技能可將技術性的 Git 提交轉換為精美、使用者友好的變更日誌，讓您的客戶與使用者能真正理解並欣賞。

## 何時使用此技能

- 為新版本準備版本資訊 (Release Notes)
- 建立每週或每月的產品更新摘要
- 為客戶記錄變更內容
- 為應用程式商店 (App Store) 提交撰寫變更說明
- 生成更新通知
- 建立內部版本文件
- 維護公共變更日誌/產品更新頁面

## 此技能的功能

1. **掃描 Git 歷史紀錄**：分析特定時間段或版本之間的 Commit。
2. **分類變更**：將 Commit 歸類至邏輯類別（功能、改進、錯誤修復、重大變更、安全更新）。
3. **技術轉化為使用者語彙**：將開發者的提交訊息轉換為客戶易懂的語言。
4. **專業格式化**：建立整潔、結構化的變更日誌項目。
5. **過濾雜訊**：排除內部提交（如重構、測試等）。
6. **遵循最佳實踐**：應用變更日誌指南並符合您的品牌語氣。

## 如何使用

### 基本用法

在您的專案儲存庫中執行：

```
根據上次發布以來的提交內容建立變更日誌
```

```
生成過去一週所有提交的變更日誌
```

```
建立版本 2.5.0 的版本資訊
```

### 指定日期範圍

```
建立 3 月 1 日至 3 月 15 日之間所有提交的變更日誌
```

### 使用自訂指南

```
從 v2.4.0 開始建立變更日誌，並參考我的 CHANGELOG_STYLE.md 指南
```

## 範例

**使用者**：「建立過去 7 天提交的變更日誌」

**輸出**：
```markdown
# 更新內容 - 2024 年 3 月 10 日當週

## ✨ 新功能

- **團隊工作區**：為不同專案建立獨立的工作區。邀請團隊成員並保持一切井然有序。

- **鍵盤快速鍵**：按下 ? 鍵查看所有可用快速鍵。無需使用滑鼠即可快速瀏覽。

## 🔧 改進

- **同步加速**：跨裝置檔案同步速度提升 2 倍。
- **搜尋優化**：搜尋現在包含檔案內容，而不僅僅是標題。

## 🐛 修復

- 修復了大尺寸圖像無法上傳的問題。
- 解決了預定貼文中的時區混亂問題。
- 修正了通知圖示的計數錯誤。
```

**靈感來自**：Lenny's Newsletter 中 Manik Aggarwal 的使用案例

## 提示 (Tips)

- 在您的 Git 儲存庫根目錄下執行。
- 指定日期範圍以便生成針對性的變更日誌。
- 使用您的 `CHANGELOG_STYLE.md` 以確保格式一致。
- 在發布前檢查並調整生成的變更日誌。
- 將輸出直接儲存到 `CHANGELOG.md`。
