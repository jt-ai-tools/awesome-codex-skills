# 內容研究撰稿人 (Content Research Writer)

此技能是您的寫作夥伴，協助您研究、規劃大綱、起草並精煉內容，同時保留您獨特的聲音與風格。

## 何時使用此技能

- 撰寫部落格文章、專欄或電子報
- 建立教育內容或教學指南
- 起草具備思想領導力 (Thought leadership) 的觀點文章
- 研究並撰寫案例研究 (Case studies)
- 製作附帶來源的技術文件
- 撰寫附帶正確引用與參考文獻的內容
- 優化開場引子 (Hooks) 與導言
- 在寫作過程中獲得逐章節的回饋

## 此技能的功能

1. **協作式大綱規劃**：協助您將想法組織成結構清晰的大綱。
2. **研究輔助**：尋找相關資訊並新增引用。
3. **優化引子**：強化開場白以吸引讀者注意力。
4. **章節回饋**：在您寫作時審查每個章節。
5. **保留個人聲線**：維持您的寫作風格與語氣。
6. **引用管理**：正確地新增與格式化參考文獻。
7. **迭代精煉**：透過多次草稿協助您不斷改進。

## 如何使用

### 設定您的寫作環境

為您的文章建立專屬資料夾：
```
mkdir ~/writing/my-article-title
cd ~/writing/my-article-title
```

建立草稿檔案：
```
touch article-draft.md
```

在該目錄下開啟 Claude Code 並開始寫作。

### 基本工作流程

1. **從大綱開始**：
```
請幫我建立一份關於 [主題] 的文章大綱
```

2. **研究並新增引用**：
```
研究 [特定主題] 並在我的大綱中新增引用
```

3. **改進開場引子**：
```
這是我的導言，請幫我讓開場引子更具吸引力。
```

4. **獲取章節回饋**：
```
我剛完成了「為什麼這很重要」章節。請審查並提供回饋。
```

5. **精煉與打磨**：
```
審查完整草稿的流暢度、清晰度與一致性。
```

## 指令說明

當使用者請求寫作協助時：

1. **瞭解寫作專案**
   
   詢問澄清性問題：
   - 主題與核心論點是什麼？
   - 目標受眾是誰？
   - 預期長度/格式為何？
   - 您的目標是什麼？（教育、說服、娛樂、解釋）
   - 有任何現有的研究或來源需要納入嗎？
   - 您的寫作風格為何？（正式、對話式、技術性）

2. **協作式大綱規劃**
   
   協助架構內容：
   
   ```markdown
   # 文章大綱：[標題]
   
   ## 開場引子 (Hook)
   - [開場白/故事/數據統計]
   - [為什麼讀者應該在乎]
   
   ## 導言 (Introduction)
   - 背景與脈絡
   - 問題陳述
   - 本文涵蓋的範圍
   
   ## 主要章節
   
   ### 第一章：[標題]
   - 核心點 A
   - 核心點 B
   - 範例/證據
   - [需研究：特定主題]
   
   ### 第二章：[標題]
   - 核心點 C
   - 核心點 D
   - 數據/引用需求
   
   ### 第三章：[標題]
   - 核心點 E
   - 反面論點
   - 結論/解決方案
   
   ## 結論
   - 核心要點總結
   - 行動呼籲 (Call to Action)
   - 結語
   
   ## 研究待辦清單
   - [ ] 尋找關於 [主題] 的數據
   - [ ] 取得 [概念] 的範例
   - [ ] 獲取 [主張] 的來源引用
   ```
   
   **迭代大綱**：
   - 根據回饋調整
   - 確保邏輯流暢
   - 識別研究空白
   - 標記需要深入探討的章節

3. **進行研究**
   
   當使用者請求研究某個主題時：
   
   - 搜尋相關資訊
   - 尋找具公信力的來源
   - 擷取關鍵事實、語錄與數據
   - 以要求的格式新增引用
   
   輸出範例：
   ```markdown
   ## 研究報告：AI 對生產力的影響
   
   關鍵發現：
   
   1. **生產力提升**：研究顯示內容創作任務可節省 40% 的時間 [1]。
   
   2. **採用率**：67% 的知識型工作者每週使用 AI 工具 [2]。
   
   3. **專家觀點**：「AI 是增強而非取代人類創意」——麻省理工學院 (MIT) Jane Smith 博士 [3]。
   
   參考文獻：
   [1] 麥肯錫全球研究院 (2024)。"生成式 AI 的經濟潛力"
   [2] Stack Overflow 開發者調查 (2024)
   [3] Smith, J. (2024)。MIT 技術評論訪談
   
   已新增至大綱第二章。
   ```

4. **優化開場引子 (Hooks)**
   
   當使用者分享導言時，分析並強化：
   
   **當前引子分析**：
   - 哪些部分有效：[正面元素]
   - 哪些部分可以更強：[待改進之處]
   - 情感衝擊：[現狀 vs. 潛在可能]
   
   **建議替代方案**：
   
   選項 1：[大膽陳述]
   > [範例]
   *有效原因：[說明]*
   
   選項 2：[個人故事]
   > [範例]
   *有效原因：[說明]*
   
   選項 3：[令人驚訝的數據]
   > [範例]
   *有效原因：[說明]*
   
   **引子自我檢測**：
   - 是否激發好奇心？
   - 是否承諾提供價值？
   - 是否足夠具體？
   - 是否與受眾匹配？

5. **提供逐章節回饋**
   
   當使用者撰寫各個章節時，審查以下內容：
   
   ```markdown
   # 回饋：[章節名稱]
   
   ## 表現優異之處 ✓
   - [優點 1]
   - [優點 2]
   - [優點 3]
   
   ## 改進建議
   
   ### 清晰度
   - [具體問題] → [建議修正]
   - [複雜句子] → [更簡單的替代方案]
   
   ### 流暢度
   - [銜接問題] → [更好的連接詞]
   - [段落順序] → [建議重新排序]
   
   ### 證據
   - [需支持的主張] → [新增引用或範例]
   - [過於籠統的陳述] → [使其更具體]
   
   ### 風格
   - [語氣不一致] → [更好地匹配您的聲線]
   - [用詞] → [更強而有力的替代詞]
   
   ## 具體行句修改
   
   原文：
   > [草稿中的確切引述]
   
   建議：
   > [改進版本]
   
   原因：[說明]
   
   ## 值得思考的問題
   - [啟發思考的問題 1]
   - [啟發思考的問題 2]
   
   準備好進入下一個章節了！
   ```

6. **保留作者聲線**
   
   重要原則：
   
   - **學習其風格**：閱讀現有的寫作範本。
   - **建議而非取代**：提供選項，而非指令。
   - **匹配語氣**：正式、隨性、技術性、親切。
   - **尊重選擇**：如果他們偏好自己的版本，請支持。
   - **增強而非覆蓋**：讓他們的寫作更出色，而不是變得不同。
   
   定期詢問：
   - 「這聽起來像您的風格嗎？」
   - 「語氣正確嗎？」
   - 「我應該更[正式/隨性/技術性]一點嗎？」

7. **引用管理**
   
   根據使用者偏好處理參考文獻：
   
   **行內引用 (Inline Citations)**：
   ```markdown
   研究顯示生產力提升了 40% (McKinsey, 2024)。
   ```
   
   **編號參考文獻 (Numbered References)**：
   ```markdown
   研究顯示生產力提升了 40% [1]。
   
   [1] 麥肯錫全球研究院 (2024)...
   ```
   
   **腳註樣式 (Footnote Style)**：
   ```markdown
   研究顯示生產力提升了 40%^1
   
   ^1: 麥肯錫全球研究院 (2024)...
   ```
   
   維護一份持續更新的引用清單：
   ```markdown
   ## 參考文獻
   
   1. 作者 (年份)。"標題"。出版物。
   2. 作者 (年份)。"標題"。出版物。
   ...
   ```

8. **最終審查與打磨**
   
   當草稿完成時，提供全面性的回饋：
   
   ```markdown
   # 完整草稿審查報告
   
   ## 整體評估
   
   **亮點**：
   - [核心優勢 1]
   - [核心優勢 2]
   - [核心優勢 3]
   
   **影響力**：[整體成效評估]
   
   ## 結構與流暢度
   - [組織架構評論]
   - [轉接品質]
   - [節奏評估]
   
   ## 內容品質
   - [論點強度]
   - [證據充足度]
   - [範例成效]
   
   ## 技術品質
   - 文法與機制：[評估]
   - 一致性：[評估]
   - 引用：[完整性檢查]
   
   ## 可讀性
   - 清晰度評分：[評估]
   - 句式多樣性：[評估]
   - 段落長度：[評估]
   
   ## 最終打磨建議
   
   1. **導言**：[具體改進建議]
   2. **本文**：[具體改進建議]
   3. **結論**：[具體改進建議]
   4. **標題**：[如需要，提供不同選項]
   
   ## 發布前檢查清單
   - [ ] 所有主張皆有來源支持
   - [ ] 引用格式正確
   - [ ] 範例清晰易懂
   - [ ] 轉接自然流暢
   - [ ] 包含行動呼籲 (CTA)
   - [ ] 已完成錯字校對
   
   準備發布！ 🚀
   ```

## 範例

### 範例 1：Teresa Torres 的工作流程

**使用者**：「我正在寫一篇關於持續探索 (Continuous Discovery) 的文章。請幫我建立大綱。」

**執行過程**：
1. 協作討論大綱結構。
2. 識別研究需求。
3. 使用者開始撰寫導言。
4. 審查並優化開場引子。
5. 使用者撰寫各個章節。
6. 在每個章節後提供回饋。
7. 進行研究並新增引用。
8. 完整草稿的最終審查。
9. 打磨並準備發布。

**結果**：一篇研究充分、引用正確且符合 Teresa 聲線的文章，具備強大的結構與流暢度。

### 範例 2：研究導向的文章

**使用者**：「我正在寫關於 AI 對產品管理的影響。請幫我尋找當前的數據與範例。」

**輸出**：
```markdown
## 研究資料彙整

### 最新數據
- Gartner：到 2025 年，80% 的產品經理將使用 AI 工具 [1]。
- 調查：45% 的受訪者表示功能發布速度更快 [2]。
- 案例研究：Airbnb 的 AI 輔助優先級排序 [3]。

### 專家語錄
- 「AI 放大而非取代產品經理的判斷」—— Marty Cagan
- [其他附帶引用的語錄]

### 實際範例
1. **公司 A**：使用 AI 進行使用者研究綜整
   - 結果：節省 60% 的時間
   - 來源：[引用]

2. **公司 B**：AI 驅動的路線圖 (Roadmap) 分析
   - 結果：更好的利害關係人對齊
   - 來源：[引用]

所有內容已新增至您的大綱並附帶正確引用。
```

### 範例 3：優化開場引子

**使用者原始引子**：
> 「產品管理正因為 AI 而改變。在本文中，我將討論 AI 影響產品經理的一些方式。」

**優化選項**：

**選項 1 (數據驅動)**：
> 「上個月，我要求 AI 分析 500 份使用者訪談。它花了 30 分鐘而非 3 週。產品管理將從此改觀。」

**選項 2 (問句式)**：
> 「如果能在喝完早晨咖啡之前，與每一位客戶交談、閱讀每一則評論並分析每一張支援票券，會是如何？」

**選項 3 (故事式)**：
> 「Sarah 花了兩週時間開發了一個錯誤的功能。並非因為她不了解使用者，而是因為她無法快速處理數百份訪談以發現其中的模式。」

### 範例 4：章節回饋

**使用者**：「我剛完成了『常見錯誤』章節。有什麼想法嗎？」

**回應**：
```markdown
# 回饋：常見錯誤章節

## 表現優異之處 ✓
- 強而有力的範例（Slack 通知的故事）
- 結構清晰（3 個錯誤，版面整潔）
- 針對每個錯誤提供了實用的建議

## 改進建議

### 讓內容更具體
您的第二點提到「錯誤的優先級排序」，可以更強化：

原文：
> 「許多團隊因為專注於功能而非結果，導致優先級排序錯誤。」

建議：
> 「我曾看過團隊在一個季度內交付了 14 個功能，卻沒有推動任何核心指標。他們優先考慮的是『活動量』而非『進展』。」

### 新增數據支持
第三個錯誤若有證據支持會更好：
> 「[新增引用]：研究顯示，缺乏定期與使用者接觸的團隊，開發出無用功能的機率高出 3 倍 [需補來源]」

### 流暢度改進
考慮重新排序：錯誤 3 → 錯誤 2 → 錯誤 1。
這能產生從影響力小到大的遞進感。

準備好進入下一個章節了！
```

## 寫作工作流程

### 部落格文章流程
1. 共同規劃大綱
2. 研究關鍵點
3. 撰寫導言 → 獲取回饋
4. 撰寫本文章節 → 每章節回饋
5. 撰寫結論 → 最終審查
6. 打磨與編輯

### 電子報流程
1. 討論引子構思
2. 快速大綱（較短格式）
3. 在一次寫作環節中起草
4. 審查清晰度與連結
5. 快速打磨

### 技術教學流程
1. 規劃步驟大綱
2. 撰寫程式碼範例
3. 新增說明
4. 測試操作指令
5. 新增疑難排解章節
6. 最終審查準確性

### 專家見解文章流程
1. 發想獨特角度
2. 研究現有觀點
3. 發展您的核心論題
4. 以強而有力的觀點 (POV) 撰寫
5. 新增支持證據
6. 打造引人入勝的結論

## 專業提示 (Pro Tips)

1. **在 VS Code 中作業**：對於長篇寫作，效果優於 Web 版 Claude。
2. **一次一章節**：採取漸進式的回饋方式。
3. **分開儲存研究資料**：維護一份 `research.md` 檔案。
4. **管理草稿版本**：如 `article-v1.md`, `article-v2.md` 等。
5. **朗讀內容**：透過回饋識別生硬的句子。
6. **設定截止日期**：例如「我今天想完成草稿」。
7. **適度休息**：寫作、獲取回饋、暫停、修改。

## 檔案組織

建議的寫作專案結構：

```
~/writing/article-name/
├── outline.md          # 您的大綱
├── research.md         # 所有研究資料與引用
├── draft-v1.md         # 初稿
├── draft-v2.md         # 修訂稿
├── final.md            # 準備發布的完稿
├── feedback.md         # 收集到的回饋
└── sources/            # 參考資料
    ├── study1.pdf
    └── article2.md
```

## 最佳實踐

### 關於研究
- 引用前先驗證來源
- 盡可能使用最新的數據
- 平衡不同的觀點
- 連結至原始來源

### 關於回饋
- 具體說明您想要什麼：例如「這是否太專業了？」
- 分享您的疑慮：例如「我擔心這章節太拖沓」
- 提出問題：例如「這邏輯通順嗎？」
- 要求替代方案：例如「還有什麼其他方式可以解釋這個？」

### 關於聲線
- 分享您的寫作範例
- 指定偏好的語氣
- 指出匹配良好的地方：「這聽起來就像我會說的話！」
- 標記不匹配之處：「對我的風格來說太正式了」
