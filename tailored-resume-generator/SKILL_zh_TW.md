# 量身定制履歷生成器 (Tailored Resume Generator)

## 何時使用此技能

- 申請特定的工作職位。
- 針對不同行業或角色自訂您的履歷。
- 在職涯轉型期間強調相關的可轉移經驗。
- 針對應徵者追蹤系統 (ATS) 優化您的履歷。
- 為不同的工作申請建立多個版本的履歷。
- 強調職位公告中提到的特定技能。

## 此技能的功能

1. **分析職位描述 (JD)**：從職位公告中擷取關鍵要求、技能、資格與關鍵字。
2. **識別優先順序**：根據 JD 的語言與結構判斷雇主最看重的是什麼。
3. **量身定制內容**：重新組織並強調相關的經驗、技能與成就。
4. **優化關鍵字**：將對 ATS 友善的關鍵字自然地融入整份履歷中。
5. **專業格式化**：建立整潔、專業且適用於各種格式的履歷佈局。
6. **提供改進建議**：提議優化方案並指出需要補充的差距。

## 如何使用

### 基本用法
提供職位描述與您的背景資訊：

```
我正在申請這份工作：

[貼上職位描述]

這是我的背景：
- 在 TechCorp 擔任 5 年軟體工程師
- 在行動 App 專案中帶領 3 名開發者團隊
- 專精於 Python, JavaScript, React
- 州立大學資訊工程學位
```

### 配合現有履歷
上傳或貼上您目前的履歷以及職位描述：

```
請針對此職位調整我的履歷：

職位描述：
[貼上職位描述]

我目前的履歷：
[貼上履歷內容]
```

### 職涯轉型
當更換行業或角色時：

```
我正從行銷轉職到產品管理。
這是我要申請的工作：

[貼上職位描述]

我的可轉移經驗：
- 7 年數位行銷經驗
- 曾帶領跨部門團隊
- 管理產品發布
- 數據分析與 A/B 測試
```

## 指令說明

當使用者請求調整履歷時：

### 1. 收集資訊

**職位描述分析**：
- 若未提供，要求完整的職位描述。
- 詢問公司名稱與職稱。

**應徵者背景**：
- 若使用者提供現有履歷，以此為基礎。
- 若無，請詢問：
  - 工作經歷（職稱、公司、日期、職責）。
  - 教育背景。
  - 核心技能與技術專長。
  - 顯著成就與量化指標。
  - 證照或獎項。
  - 其他任何相關資訊。

### 2. 分析職位要求

擷取並排序優先級：
- **必備資格**：年資、必備技能、教育程度。
- **核心技能**：技術工具、方法論、職能。
- **軟實力**：溝通、領導力、團隊合作。
- **產業知識**：特定領域經驗。
- **關鍵字**：JD 中重複出現的術語、短語，用於 ATS 優化。
- **公司價值觀**：從 JD 中看出的文化契合度指標。

建立心理地圖：
- 優先級 1：關鍵要求（硬性條件）。
- 優先級 2：重要資格（強烈偏好）。
- 優先級 3：加分技能（額外優勢）。

### 3. 將應徵者經驗對映至要求

針對每項職位要求：
- 從應徵者背景中識別匹配的經驗。
- 若無直接匹配，尋找可轉移技能。
- 標註需要處理或淡化的差距。
- 識別要強調的獨特優勢。

### 4. 架構量身定制的履歷

**專業總結** (3-4 行)：
- 以目標角色/領域的年資開頭。
- 包含 JD 中前 3-4 項要求的技能。
- 提及產業經驗（若相關）。
- 強調獨特價值主張。

**技術/核心技能章節**：
- 按符合職位要求的類別對技能進行分組。
- 優先列出要求的工具與技術。
- 使用與 JD 完全一致的術語。
- 僅列出您可以用經驗證明的技能。

**專業經驗**：
- 針對每個角色，強調與職位要求一致的職責與成就。
- 使用行動動詞：Led (領導), Developed (開發), Implemented (實作), Optimized (優化), Managed (管理), Created (建立), Analyzed (分析)。
- **量化成就**：包含數字、百分比、時間範圍、規模。
- 重新排列列點順序，優先展示最相關的經驗。
- 自然地使用來自 JD 的關鍵字。
- 格式：**[行動動詞] + [做了什麼] + [如何做/為什麼做] + [結果/影響]**。

**教育背景**：
- 列出與職位相關的學位、證照。
- 若為職場新人，包含相關課程。
- 加入符合要求的專業證照。

**選填章節**（若適用）：
- 證照與執照。
- 出版物或演講經歷。
- 獎項與榮譽。
- 志工服務（若與角色相關）。
- 專案作品（特別是技術類角色）。

### 5. 針對應徵者追蹤系統 (ATS) 進行優化

- 使用標準章節標題（專業經驗、教育背景、技能）。
- 自然融入來自 JD 的精確關鍵字。
- 避免使用表格、圖形、頁首/頁尾或複雜格式。
- 使用標準字體與項目符號。
- 同時包含縮寫與全稱（例如：「SQL (結構化查詢語言)」）。
- 在誠實的前提下，匹配職稱術語。

### 6. 格式化與呈現

**格式選項**：
- **Markdown**：整潔、易讀、方便複製。
- **純文字**：ATS 優化，適用於所有系統。
- **Word/PDF 提示**：提供格式設定指引。

**履歷結構指南**：
- 10 年以下經驗保持在 1 頁，10 年以上可至 2 頁。
- 使用一致的格式與間距。
- 確保聯絡資訊顯眼。
- 使用倒序排列（最近的經歷放在最前面）。
- 保持版面整潔、留白適當，方便快速瀏覽。

### 7. 提供策略性建議

呈現履歷後，提供：

**優勢分析**：
- 是什麼讓應徵者具備競爭力。
- 應在求職信或面試中強調的獨特資格。

**差距分析**：
- 未完全符合的要求。
- 填補差距的建議（課程、專案、重新包裝經驗）。

**面試準備提示**：
- 與履歷一致的關鍵談話要點。
- 根據職位要求準備的故事/案例。
- 展現契合度的提問建議。

**求職信 (Cover Letter) 引子**：
- 建議 2-3 個求職信開場白。
- 可進一步發揮的關鍵成就。

### 8. 迭代與精煉

詢問使用者是否需要：
- 調整側重點或語氣。
- 新增或移除章節。
- 生成針對不同角色的替代版本。
- 建立格式變體（傳統 vs. 現代）。
- 開發角色特定版本（若同時申請多個相似職位）。

### 9. 應遵循的最佳實踐

**要做的 (Do)**：
- 保持真實準確——絕不捏造經驗。
- 使用產業標準術語。
- 使用具體指標量化成就。
- 為每個特定工作量身定制履歷。
- 校對語法與一致性。
- 語言簡潔且具影響力。

**不要做的 (Don't)**：
- 包含個人資訊（年齡、婚姻狀況、除非要求否則不放照片）。
- 使用第一人稱代名詞（我、我的）。
- 包含推薦人（「應要求提供」已過時）。
- 若職涯超過 20 年，不要列出每一份工作（專注於相關且近期的經驗）。
- 使用未經自訂的通用模板。
- 除非是非常資深的職位，否則不要超過 2 頁。

### 10. 特殊考量因素

**轉職者**：
- 使用功能型 (Functional) 或混合型履歷格式。
- 強調可轉移技能。
- 在總結中建立具吸引力的敘事。
- 專注於相關專案與課程。

**社會新鮮人**：
- 教育背景置前。
- 包含相關課程、專案、實習。
- 強調在學生社團中的領導力。
- 若 GPA 高於 3.5 則包含在內。

**高階主管**：
- 執行摘要置前。
- 專注於領導力與戰略影響。
- 包含董事會成員經歷、演講邀約。
- 強調營收增長、團隊建設、願景。

**技術類角色**：
- 顯著展示技術技能章節。
- 列出程式語言、框架、工具。
- 包含 GitHub、作品集或專案連結。
- 提及方法論（Agile, Scrum 等）。

**創意類角色**：
- 包含作品集連結。
- 強調創意成就與作品。
- 提及工具與軟體熟練度。
- 考慮更具創意的格式（同時保持 ATS 相容性）。

## 獲得最佳結果的提示

- **具體化**：提供完整的職位描述與詳細的背景資訊。
- **分享指標**：在描述經驗時包含數字、百分比與可量化的成就。
- **說明格式偏好**：告知您需要 ATS 優化、創意型還是傳統型格式。
- **提及限制條件**：分享任何特定要求（頁數限制、要包含/排除的章節）。
- **迭代**：不要猶豫要求修改或嘗試不同的處理方式。
- **多重申請**：為不同角色生成獨立的量身定制版本。

## 隱私註記

此技能會處理您的個人與專業資訊以生成量身定制的履歷。在提交之前，請務必審查輸出內容以確保準確性與適當性。移除或修改任何您不希望與潛在雇主分享的資訊。
