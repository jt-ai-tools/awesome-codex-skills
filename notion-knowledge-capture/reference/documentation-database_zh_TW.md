# 通用技術文件資料庫 (General Documentation Database)

**目的**：將所有類型的文件儲存在一個可搜尋、有組織的資料庫中。

## 結構綱要 (Schema)

| 屬性 | 型別 | 選項 | 目的 |
|----------|------|---------|---------|
| **標題** | title | - | 文件名稱 |
| **類型** | select | 操作指南 (How-To), 概念, 參考, FAQ, 決策, 事後檢討 (Post-Mortem) | 內容類型分類 |
| **類別** | select | 工程, 產品, 設計, 營運, 一般 | 按部門/主題組織 |
| **標籤** | multi_select | - | 額外分類（語言、工具、主題） |
| **狀態** | select | 草稿, 審查中, 定稿, 已棄用 | 追蹤文件生命週期 |
| **負責人** | people | - | 文件維護者 |
| **建立時間** | created_time | - | 自動生成的建立日期 |
| **最後更新** | last_edited_time | - | 自動生成的最後修改日期 |
| **最後審查日** | date | - | 手動追蹤審查進度 |

## 使用方式

```
建立包含以下屬性的頁面：
{
  "標題": "如何部署到生產環境",
  "類型": "操作指南 (How-To)",
  "類別": "工程",
  "標籤": "deployment, production, DevOps",
  "狀態": "定稿",
  "負責人": [當前使用者],
  "最後審查日": "2025-10-01"
}
```

## 檢視表 (Views)

**按類型分類**：按「類型」屬性分組。
**按類別分類**：按「類別」屬性分組。
**近期更新**：按「最後更新」降序排列。
**需要審查**：過濾「最後審查日」早於 90 天前的項目。
**草稿文件**：過濾狀態為「草稿」的項目。

## 建立此資料庫

使用 `Notion:notion-create-database` 指令：

```javascript
{
  "parent": {"page_id": "wiki-page-id"},
  "title": [{"text": {"content": "團隊技術文件"}}],
  "properties": {
    "類型": {
      "select": {
        "options": [
          {"name": "操作指南 (How-To)", "color": "blue"},
          {"name": "概念", "color": "green"},
          {"name": "參考", "color": "gray"},
          {"name": "FAQ", "color": "yellow"}
        ]
      }
    },
    "類別": {
      "select": {
        "options": [
          {"name": "工程", "color": "red"},
          {"name": "產品", "color": "purple"},
          {"name": "設計", "color": "pink"}
        ]
      }
    },
    "標籤": {"multi_select": {"options": []}},
    "負責人": {"people": {}},
    "狀態": {
      "select": {
        "options": [
          {"name": "草稿", "color": "gray"},
          {"name": "定稿", "color": "green"},
          {"name": "已棄用", "color": "red"}
        ]
      }
    }
  }
}
```

## 最佳實踐

1. **從此結構綱要開始** —— 對通用文件而言最具靈活性。
2. **使用關聯**來連接相關的文件。
3. **為常見使用場景建立檢視表**。
4. **每季審查屬性** —— 移除未使用的屬性。
5. **在資料庫描述中記錄結構綱要**。
6. **培訓團隊**了解屬性的用法與慣例。
