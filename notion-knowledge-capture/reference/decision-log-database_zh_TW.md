# 決策日誌資料庫 (架構決策紀錄 - ADR)

**目的**：追蹤重要決策，並提供背景資訊與決策理由。

## 結構綱要 (Schema)

| 屬性 | 型別 | 選項 | 目的 |
|----------|------|---------|---------|
| **決策事項** | title | - | 決定的內容為何 |
| **日期** | date | - | 決策做出的時間 |
| **狀態** | select | 提案中 (Proposed), 已接受 (Accepted), 已取代 (Superseded), 已棄用 (Deprecated) | 當前決策狀態 |
| **領域** | select | 架構, 產品, 業務, 設計, 營運 | 決策類別 |
| **影響程度** | select | 高, 中, 低 | 預期的影響等級 |
| **決策者** | people | - | 誰做出的決策 |
| **利害關係人** | people | - | 誰會受此決策影響 |
| **相關決策** | relation | 連結至其他決策 | 脈絡與依賴關係 |

## 使用方式

```
建立包含以下屬性的決策紀錄：
{
  "決策事項": "使用 PostgreSQL 作為主要資料庫",
  "日期": "2025-10-15",
  "狀態": "已接受",
  "領域": "架構",
  "影響程度": "高",
  "決策者": [技術主管, 架構師],
  "利害關係人": [工程團隊]
}
```

## 內容模板

每個決策頁面應包含：
- **背景 (Context)**：為什麼需要做出此決策。
- **決策內容 (Decision)**：具體決定了什麼。
- **理由 (Rationale)**：為什麼選擇此方案。
- **曾考慮的選項 (Options Considered)**：其他替代方案及其權衡 (Trade-offs)。
- **後續影響 (Consequences)**：預期的結果（正面與負面）。
- **實作方式 (Implementation)**：決策將如何執行。

## 檢視表 (Views)

**近期決策**：按日期降序排列。
**有效決策**：過濾狀態為「已接受」的項目。
**按領域分類**：按領域進行分組。
**高影響力**：過濾影響程度為「高」的項目。
**待定事項**：過濾狀態為「提案中」的項目。

## 最佳實踐

1. **即時記錄**：在決策做出、背景資訊尚清晰時立即記錄。
2. **包含替代方案**：展示考慮過哪些選項以及未選中的原因。
3. **追蹤被取代的決策**：當決策變更時及時更新狀態。
4. **連結相關決策**：使用關聯屬性展示依賴關係。
5. **定期審查**：檢查舊決策是否依然有效。
