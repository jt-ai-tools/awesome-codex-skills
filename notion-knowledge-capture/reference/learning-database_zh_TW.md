# 學習與檢討資料庫 (Learning/Post-Mortem Database)

**目的**：擷取來自事件、專案或經驗的學習心得。

## 結構綱要 (Schema)

| 屬性 | 型別 | 選項 | 目的 |
|----------|------|---------|---------|
| **標題** | title | - | 事件或專案名稱 |
| **日期** | date | - | 發生時間 |
| **類型** | select | 事件 (Incident), 專案, 實驗, 回顧 (Retrospective) | 學習心得類型 |
| **嚴重程度** | select | 緊急 (Critical), 重大, 次要 | 影響等級（針對事件） |
| **團隊** | people | - | 參與人員 |
| **關鍵心得數** | number | - | 學習要點的數量 |
| **行動項目** | relation | 連結至任務 | 後續改進動作 |

## 內容模板

每個學習頁面應包含：
- **發生了什麼 (What Happened)**：情況描述。
- **哪些進展順利 (What Went Well)**：成功因素。
- **哪些進展不順 (What Didn't Go Well)**：遇到的問題。
- **根本原因 (Root Causes)**：發生的原因。
- **學習心得 (Learnings)**：核心心得與收穫。
- **行動項目 (Action Items)**：待實施的改進措施。

## 最佳實踐

1. **無責文化 (Blameless approach)**：關注系統與流程，而非個人。
2. **及時記錄**：在記憶猶新時儘快擷取資訊。
3. **識別根本原因**：深入挖掘，不侷限於表面問題。
4. **建立行動項目**：將學習心得轉化為實質改進。
5. **後續追蹤**：追蹤並確保行動項目已完成。
6. **廣泛分享**：讓全團隊都能獲取這些學習心得。
