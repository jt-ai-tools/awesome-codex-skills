# 會議洞察分析工具 (Meeting Insights Analyzer)

此技能可將您的會議逐字稿轉化為關於您溝通模式的具體洞察，協助您成為更有效的溝通者與領導者。

## 何時使用此技能

- 分析您在多次會議中的溝通模式。
- 獲取關於您領導與引導風格的回饋。
- 識別您何時在迴避困難的對話。
- 瞭解您的說話習慣與贅字 (Filler words) 使用情況。
- 追蹤溝通技巧隨時間的進步情況。
- 使用具體範例為績效評估 (Performance reviews) 做準備。
- 指導團隊成員改善其溝通風格。

## 此技能的功能

1. **模式識別**：識別會議中重複出現的行為，例如：
   - 衝突迴避或間接溝通。
   - 發言比例與發言輪替 (Turn-taking)。
   - 提問與陳述的比例模式。
   - 積極聆聽的指標。
   - 決策方法。

2. **溝通分析**：評估溝通成效：
   - 清晰度與直接程度。
   - 贅字與委婉措辭 (Hedging language) 的使用。
   - 語氣與情緒模式。
   - 會議掌控與引導。

3. **具引導性的回饋**：提供附帶時間戳記的具體範例，包含：
   - 發生了什麼事。
   - 為什麼這很重要。
   - 如何改進。

4. **趨勢追蹤**：在分析多次會議時，比較模式隨時間的變化。

## 如何使用

### 基本設定

1. 將您的會議逐字稿下載至一個資料夾（例如 `~/meetings/`）。
2. 在 Codex 中導航至該資料夾。
3. 要求您想要的分析內容。

### 快速開始範例

```
分析此資料夾中的所有會議，並告訴我何時我在迴避衝突。
```

```
查看我過去一個月的會議，並識別我的溝通模式。
```

```
比較這兩個會議資料夾中我的引導風格差異。
```

### 進階分析

```
分析此資料夾中的所有逐字稿，並且：
1. 識別我何時打斷了別人
2. 計算我的發言比例
3. 找出我避免給予直接回饋的時刻
4. 追蹤我贅字的使用情況
5. 展示表現良好的積極聆聽範例
```

## 指令說明

當使用者請求會議分析時：

1. **探索可用數據**
   - 掃描資料夾中的逐字稿檔案（.txt, .md, .vtt, .srt, .docx）。
   - 檢查檔案是否包含講者標籤與時間戳記。
   - 確認會議的日期範圍。
   - 在逐字稿中識別使用者的姓名/標識符。

2. **澄清分析目標**
   
   若未指定，詢問他們想瞭解什麼：
   - 特定行為（衝突迴避、打斷、贅字）。
   - 溝通成效（清晰度、直接性、聆聽）。
   - 會議引導技巧。
   - 說話模式與比例。
   - 待改進的成長領域。
   
3. **分析模式**

   針對每項要求的洞察：
   
   **衝突迴避 (Conflict Avoidance)**：
   - 尋找委婉措辭（「可能」、「大概」、「我覺得」）。
   - 使用間接語句而非直接要求。
   - 當氣氛緊張時變更話題。
   - 表面同意但缺乏承諾（「對，但是...」）。
   - 未處理明顯的問題。
   
   **發言比例 (Speaking Ratios)**：
   - 計算會議中發言時間的百分比。
   - 統計打斷次數（使用者打斷別人及被別人打斷）。
   - 測量平均每回合發言長度。
   - 追蹤提問與陳述的比例。
   
   **贅字 (Filler Words)**：
   - 統計「嗯」、「那個」、「就是」、「然後」等頻率。
   - 紀錄每分鐘或每回合發言的出現次數。
   - 識別贅字增加的情境（緊張、不確定時）。
   
   **積極聆聽 (Active Listening)**：
   - 提問中是否引用了他人先前的觀點。
   - 轉述或總結他人的想法。
   - 在他人的貢獻基礎上進一步發揮。
   - 提出澄清性問題。
   
   **領導力與引導 (Leadership & Facilitation)**：
   - 決策方式（指令式 vs. 協作式）。
   - 如何處理分歧。
   - 是否納入較沉默的參與者。
   - 時間管理與議程掌控。
   - 後續行動與行動項目的清晰度。

4. **提供具體範例**

   針對發現的每種模式，包含：
   
   ```markdown
   ### [模式名稱]
   
   **發現**：[該模式的一句話總結]
   
   **頻率**：[在 Y 場會議中出現 X 次]
   
   **範例**：
   
   1. **[會議名稱/日期]** - [時間戳記]
      
      **當時情況**：
      > [逐字稿中的實際引述]
      
      **為什麼這很重要**：
      [解釋影響或錯失的機會]
      
      **更好的做法**：
      [具體的替代說法或行為建議]
   
   [重複列出 2-3 個最具代表性的範例]
   ```

5. **綜整洞察**

   分析完所有模式後，提供：
   
   ```markdown
   # 會議洞察總結報告
   
   **分析期間**：[日期範圍]
   **分析場次**：[X 場會議]
   **總時數**：[X 小時]
   
   ## 識別出的關鍵模式
   
   ### 1. [主要模式]
   - **觀察到的現象**：[您看到的內容]
   - **影響**：[為什麼這很重要]
   - **建議**：[如何改進]
   
   ### 2. [次要模式]
   [相同結構]
   
   ## 溝通優勢
   
   1. [優勢 1 及其範例]
   2. [優勢 2 及其範例]
   3. [優勢 3 及其範例]
   
   ## 成長機會
   
   1. **[領域 1]**：[具體、可執行的建議]
   2. **[領域 2]**：[具體、可執行的建議]
   3. **[領域 3]**：[具體、可執行的建議]
   
   ## 發言數據統計
   
   - 平均發言時間：[佔會議的 X%]
   - 提問次數：[平均每場 X 次]
   - 贅字頻率：[每分鐘 X 個]
   - 打斷統計：[每場發起 X 次 / 遭遇 Y 次]
   
   ## 後續行動
   
   [3-5 個改進溝通的具體行動]
   ```

6. **提供後續選項**
   - 在未來的會議中持續追蹤這些指標。
   - 深入探討特定會議或模式。
   - 與行業基準進行比較。
   - 建立個人溝通發展計畫。
   - 為績效評估生成摘要。

## 範例

### 範例 1：衝突迴避分析（靈感來自 Dan Shipper）

**使用者**：「我下載了所有的會議錄音並放在一個資料夾裡。告訴我所有我微妙地迴避衝突的時刻。」

**輸出**： 
```markdown
# 衝突迴避模式分析

在 15 場會議中發現了 23 處您使用間接溝通或避免直接處理緊張氣氛的情況。

## 模式：在關鍵回饋上使用委婉措辭

**頻率**：7 場會議中出現 8 次

**範例 1：與 Sarah 的 1:1 面談** - 00:14:32

**當時情況**：
> 「所以，我在想... 也許我們，那個，可以考慮重新看一下時程表？我是說，如果你
> 覺得這樣有道理的話。但不管你覺得怎麼做最好都行！」

**為什麼這很重要**：
您需要處理 Sarah 的專案進度落後的問題，但委婉措辭（「也許」、「考慮」、「如果你覺得」）以及最後的推託（「不管你覺得怎樣都行」）讓她很容易忽略事情的緊迫性。

**更好的做法**：
「Sarah，專案目前落後進度兩週。我們今天需要討論是什麼阻礙了進展，並制定一個新的時程表。」

[更多範例...]

## 建議事項

1. **在第一句話就直接指名問題**。
2. **移除委婉贅字**，如「可能」、「好像」、「大概」。
3. **提出具體問題**而非暗示。
4. **預約困難對話的時間**，而非隨口提及。
```

### 範例 2：領導引導力

**使用者**：「分析我的團隊會議並告訴我關於我的引導風格。」

**輸出**：提供關於以下方面的洞察：
- 您與團隊成員的發言比例 (60% vs. 40%)。
- 您是在提問還是在陳述 (3:1 比例)。
- 您如何處理分歧（是否有過早解決問題的傾向）。
- 誰發言最少，以及您是否引導他們參與。
- 表現優異與錯失機會的引導時刻範例。

### 範例 3：個人發展追蹤

**使用者**：「比較我第一季與第二季的會議，看看我的聆聽技巧是否有進步。」

**輸出**：建立對比分析，顯示：
- 打斷次數減少（每場 8 次 → 3 次）。
- 澄清性提問增加（每場 2 次 → 7 次）。
- 在他人想法基礎上進一步發揮的能力有所提升。
- 顯示差異的具體範例。
- 剩餘的待成長領域。

## 設定提示

### 獲取會議逐字稿

**從 Granola 獲取**：
- Granola 會自動為您的會議產出逐字稿。
- 將逐字稿匯出到資料夾。
- 將 Codex 指向該資料夾。

**從 Zoom 獲取**：
- 啟用帶有逐字稿功能的雲端錄製。
- 會後下載 VTT 或 SRT 檔案。
- 存儲在專屬資料夾中。

**從 Google Meet 獲取**：
- 使用 Google Docs 自動逐字稿功能。
- 將逐字稿文件儲存在資料夾中。
- 下載為 .txt 檔案或授予 Codex 存取權限。

**從 Fireflies.ai, Otter.ai 等獲取**：
- 批量匯出逐字稿。
- 儲存在本地資料夾。
- 對該資料夾執行分析。

### 最佳實踐

1. **一致的命名**：使用 `YYYY-MM-DD - 會議名稱.txt` 格式。
2. **定期分析**：每月或每季審查趨勢。
3. **具體查詢**：一次詢問一種行為以獲得深度分析。
4. **隱私保護**：將敏感的會議數據保存在本地。
5. **行動導向**：一次專注於一個改進領域。

## 常見分析請求

- 「我何時在迴避困難的對話？」
- 「我打斷別人的頻率是多少？」
- 「我的說話與聆聽比例為何？」
- 「我是否提出了好的問題？」
- 「我如何處理分歧？」
- 「我是否納入了所有人的聲音？」
- 「我是否使用了太多的贅字？」
- 「我的行動項目有多清晰？」
- 「我是否遵循議程，還是容易偏離主題？」
- 「我的溝通方式隨時間發生了什麼變化？」
