# 檔案整理工具 (File Organizer)

此技能就像您的個人整理助理，協助您在電腦上維持整潔、具邏輯性的檔案結構，讓您不必再為了繁瑣的手動整理而產生心理負擔。

## 何時使用此技能

- 您的「下載」資料夾一片混亂
- 因為檔案散落各處而找不到東西
- 有許多重複檔案佔用空間
- 資料夾結構不再具備邏輯性
- 您想建立更好的整理習慣
- 您正要開始一個新專案並需要良好的結構
- 您要在封存舊專案前進行清理

## 此技能的功能

1. **分析當前結構**：審查您的資料夾與檔案以了解現況。
2. **尋找重複檔案**：識別您系統中的重複檔案。
3. **建議整理方案**：根據內容提議邏輯性的資料夾結構。
4. **自動化清理**：在獲得您批准後移動、重新命名並整理檔案。
5. **保持上下文關聯**：根據檔案類型、日期與內容做出智慧決策。
6. **減少雜亂**：識別您可能不再需要的舊檔案。

## 指令說明

當使用者請求檔案整理協助時：

1. **了解範圍**
   
   詢問澄清性問題：
   - 哪個目錄需要整理？（下載、文件、還是整個家目錄？）
   - 主要問題是什麼？（找不到東西、重複檔案、太亂、沒有結構？）
   - 有哪些檔案或資料夾需要避開？（目前的專案、敏感數據？）
   - 整理的強度為何？（保守清理 vs. 全面清理）

2. **分析當前狀態**
   
   審查目標目錄：
   ```bash
   # 獲取當前結構概覽
   ls -la [目標目錄]
   
   # 檢查檔案類型與大小
   find [目標目錄] -type f -exec file {} \; | head -20
   
   # 識別最大的檔案
   du -sh [目標目錄]/* | sort -rh | head -20
   
   # 統計檔案類型
   find [目標目錄] -type f | sed 's/.*\.//' | sort | uniq -c | sort -rn
   ```
   
   總結發現：
   - 檔案與資料夾總數
   - 檔案類型分佈
   - 大小分佈
   - 日期範圍
   - 明顯的整理問題

3. **識別整理模式**
   
   根據檔案屬性決定邏輯分組：
   
   **按類型**：
   - 文件 (PDF, DOCX, TXT)
   - 圖像 (JPG, PNG, SVG)
   - 影片 (MP4, MOV)
   - 壓縮檔 (ZIP, TAR, DMG)
   - 程式碼/專案 (包含程式碼的目錄)
   - 試算表 (XLSX, CSV)
   - 簡報 (PPTX, KEY)
   
   **按用途**：
   - 工作 vs. 個人
   - 活躍 vs. 封存
   - 特定專案
   - 參考資料
   - 暫存檔/草稿檔
   
   **按日期**：
   - 當前年份/月份
   - 往年
   - 極舊檔案（封存候選）

4. **尋找重複檔案**
   
   根據要求搜尋重複項：
   ```bash
   # 透過雜湊值 (Hash) 尋找完全相同的重複檔案
   find [目錄] -type f -exec md5 {} \; | sort | uniq -d
   
   # 尋找檔名相同的檔案
   find [目錄] -type f -printf '%f
' | sort | uniq -d
   
   # 尋找大小相似的檔案
   find [目錄] -type f -printf '%s %p
' | sort -n
   ```
   
   針對每組重複檔案：
   - 顯示所有檔案路徑
   - 顯示大小與修改日期
   - 建議保留哪一個（通常是最新或命名最清晰的）
   - **重要**：刪除前務必徵詢確認

5. **提出整理計畫**
   
   在執行變更前呈現清晰的計畫：
   
   ```markdown
   # [目錄] 整理計畫
   
   ## 當前狀態
   - 分散於 Y 個資料夾中的 X 個檔案
   - 總計 [大小]
   - 檔案類型：[分佈情況]
   - 問題：[列出問題點]
   
   ## 建議結構
   
   ```
   [目錄]/
   ├── Work/ (工作)
   │   ├── Projects/ (專案)
   │   ├── Documents/ (文件)
   │   └── Archive/ (封存)
   ├── Personal/ (個人)
   │   ├── Photos/ (照片)
   │   ├── Documents/ (文件)
   │   └── Media/ (媒體)
   └── Downloads/ (下載)
       ├── To-Sort/ (待分類)
       └── Archive/ (封存)
   ```
   
   ## 我將執行的變更
   
   1. **建立新資料夾**：[列表]
   2. **移動檔案**：
      - X 個 PDF → Work/Documents/
      - Y 張圖片 → Personal/Photos/
      - Z 個舊檔案 → Archive/
   3. **重新命名檔案**：[任何命名模式]
   4. **刪除**：[重複檔案或垃圾檔案]
   
   ## 需要您決定的檔案
   
   - [列出任何不確定的檔案]
   
   準備好開始了嗎？ (yes/no/modify)
   ```

6. **執行整理**
   
   獲准後，有系統地進行整理：
   
   ```bash
   # 建立資料夾結構
   mkdir -p "path/to/new/folders"
   
   # 移動檔案並記錄日誌
   mv "old/path/file.pdf" "new/path/file.pdf"
   
   # 以一致的模式重新命名檔案
   # 範例："YYYY-MM-DD - 描述.ext"
   ```
   
   **重要規則**：
   - 刪除任何東西前務必確認
   - 記錄所有搬移路徑以便還原
   - 保留原始修改日期
   - 優雅地處理檔名衝突
   - 遇到意外狀況時停止並詢問

7. **提供總結與維護提示**
   
   整理完成後：
   
   ```markdown
   # 整理完成！ ✨
   
   ## 變更內容
   
   - 建立了 [X] 個新資料夾
   - 整理了 [Y] 個檔案
   - 透過移除重複檔案釋放了 [Z] GB 空間
   - 封存了 [W] 個舊檔案
   
   ## 新結構
   
   [顯示新的資料夾樹狀圖]
   
   ## 維護提示
   
   要保持整潔：
   
   1. **每週**：分類新的下載檔案
   2. **每月**：審查並封存已完成的專案
   3. **每季**：檢查新的重複檔案
   4. **每年**：封存舊檔案
   
   ## 您的快速指令
   
   ```bash
   # 尋找本週修改的檔案
   find . -type f -mtime -7
   
   # 按類型排序下載檔案
   [針對其設定的自訂指令]
   
   # 尋找重複檔案
   [自訂指令]
   ```
   
   想整理另一個資料夾嗎？
   ```

## 範例

### 範例 1：整理下載資料夾 (源自 Justin Dielmann)

**使用者**：「我的『下載』資料夾很亂，有 500 多個檔案。幫我整理一下。」

**執行過程**：
1. 分析「下載」資料夾。
2. 尋找模式：工作文件、個人照片、安裝程式、隨機的 PDF。
3. 建議結構：
   - Downloads/
     - Work/
     - Personal/
     - Installers/ (DMG, PKG 檔案)
     - Archive/
     - ToSort/ (需要決定的項目)
4. 要求確認。
5. 根據內容與名稱智慧搬移檔案。
6. 結果：500 個檔案 → 5 個整齊的資料夾。

**使用者**：「尋找我『文件』資料夾中的重複檔案，並幫我決定保留哪一個。」

**輸出**：

## 重複組別 1："proposal.pdf"

**建議**：保留 `/Documents/proposal.pdf`（位置正確且日期最新）
刪除其他 2 個副本嗎？

[繼續列出所有重複檔案...]
```

### 範例 3：重構專案資料夾

**使用者**：「審查我的 ~/Projects 目錄並建議改進方案。」

**輸出**：
```markdown
# ~/Projects 分析報告

## 當前結構問題
- 活躍專案與封存專案混雜（有些已超過 3 年）
- 命名慣例不一致
- 部分專案在根目錄，有些在隨機的子資料夾
- 有重複的資料夾（project-name, project-name-old, project-name-v2）

## 建議結構

```
Projects/
├── Active/ (活躍專案)
│   ├── client-work/ (客戶工作)
│   ├── side-projects/ (側邊專案)
│   └── learning/ (學習)
├── Archive/ (封存)
│   ├── 2022/
│   ├── 2023/
│   └── 2024/
└── Templates/ (模板)
```

## 具體變更
1. 將 12 個自 2022 年後未碰過的專案移動至 → Archive/
2. 整合 4 個重複的專案資料夾
3. 將專案重新命名為一致的格式："客戶名稱-專案名稱"
4. 為舊工作建立封存區

要讓我執行嗎？
```

## 專業提示 (Pro Tips)

1. **從小處開始**：先從一個混亂的資料夾（如「下載」）開始以建立信任。
2. **定期維護**：每週對「下載」資料夾執行一次清理。
3. **一致的命名**：重要檔案使用 "YYYY-MM-DD - 描述" 格式。
4. **積極封存**：將舊專案移至封存區而非直接刪除。
5. **保持活躍區獨立**：在活躍工作與封存工作之間維持清晰的邊界。
6. **相信流程**：讓 Claude 承擔「東西該放哪」的認知負擔。

## 最佳實踐

### 資料夾命名
- 使用清晰、具描述性的名稱
- 避免使用空格（使用連字號 - 或底線 _ ）
- 要具體：例如 "client-proposals" 而非 "docs"
- 使用前綴進行排序：例如 "01-current", "02-archive"

### 檔案命名
- 包含日期：例如 "2024-10-17-meeting-notes.md"
- 具描述性：例如 "q3-financial-report.xlsx"
- 避免在名稱中包含版本號（改用版本控制系統）
- 移除下載產生的重複後綴：例如 "document-final-v2 (1).pdf" → "document.pdf"

### 何時該封存
- 超過 6 個月未碰過的專案
- 未來可能需要參考的已完成工作
- 遷移到新系統後的舊版本
- 您猶豫是否要刪除的檔案（先封存再說）
