# 從規格書到實作技能評估 (Spec to Implementation Skill Evaluations)

用於測試不同 Codex 模型下「從規格書到實作 (Spec to Implementation)」技能的評估場景。

## 目的

這些評估旨在確保「從規格書到實作」技能能夠：
- 準確地尋找並解析規格書頁面。
- 將規格書拆解為具引導性的實作計畫。
- 建立具備清晰驗收標準、且 Codex 可實作的任務。
- 追蹤進度並更新實作狀態。
- 在 Haiku, Sonnet 與 Opus 模型上保持一致的表現。

## 評估檔案說明

### basic-spec-implementation.json
測試將規格書轉化為實作計畫的基礎工作流程。

**場景**：根據規格書實作使用者認證功能。
**關鍵行為**：
- 搜尋並找到認證規格書頁面。
- 獲取規格書並擷取需求。
- 將需求解析為不同階段（設定、核心功能、精煉）。
- 建立連結至原始規格書的實作計畫頁面。
- 拆解為具備明確交付物的清晰階段。
- 包含時程預估與依賴關係。

### spec-to-tasks.json
測試在任務資料庫中，根據規格書建立具體任務。

**場景**：根據 API 重新設計規格書建立任務。
**關鍵行為**：
- 在 Notion 中找到規格書頁面。
- 擷取具體需求與驗收標準。
- 搜尋或建立任務資料庫。
- 獲取任務資料庫結構綱要。
- 建立多個具備正確屬性（狀態、優先級、衝刺週期等）的任務。
- 每個任務都有清晰的標題、描述與驗收標準。
- 在適當處設定任務間的依賴關係。
- 將所有任務連回原始規格書。

## 執行評估

1. 啟用 `spec-to-implementation` 技能。
2. 提交評估檔案中的查詢語句。
3. 驗證技能是否透過搜尋找到規格書頁面。
4. 檢查需求是否被準確解析。
5. 確認實作計畫是否按階段建立。
6. 驗證任務是否具備清晰、可實作的驗收標準。
7. 檢查任務是否連結回規格書。
8. 使用 Haiku, Sonnet 與 Opus 進行測試。

## 預期的技能行為

從規格書到實作的評估應驗證以下事項：

### 規格書發現與解析
- 在 Notion 中搜尋規格說明頁面。
- 獲取完整的規格書內容。
- 準確擷取所有需求。
- 識別技術依賴關係。
- 理解驗收標準。
- 註記任何模糊之處或缺失細節。

### 實作規劃
- 建立實作計畫頁面。
- 將工作拆解為邏輯階段：
  - 第一階段：基礎建設/設定。
  - 第二階段：核心實作。
  - 第三階段：測試與精煉。
- 包含預估時程。
- 識別階段間的依賴關係。
- 連結回原始規格書。

### 任務建立
- 尋找或識別任務資料庫。
- 獲取資料庫結構綱要以確定屬性名稱。
- 建立具備正確屬性的任務。
- 每個任務包含：
  - 清晰、具體的標題。
  - 背景資訊與描述。
  - 驗收標準（檢查清單格式）。
  - 合適的優先級與狀態。
  - 指向規格書頁面的連結。
- 任務規模適中（不過大也不過小）。
- 註記任務間的依賴關係。

### 進度追蹤
- 實作計畫中包含進度標記。
- 任務可隨著工作進展進行更新。
- 狀態更新連結至已完成的工作。
- 註記阻礙因素或變更。

## 建立新評估

新增從規格書到實作評估時：

1. **測試不同的規格書類型**：功能開發、遷移、重構、API 變更、UI 組件。
2. **變化複雜度**：單一階段 vs. 複雜的多階段實作。
3. **測試任務細緻度**：是否建立了規模適當的任務？
4. **包含邊緣案例**：模糊的規格書、矛盾的需求、缺失的細節。
5. **測試資料庫整合**：在具備各種結構綱要的現有任務資料庫中建立任務。
6. **進度追蹤**：隨著任務完成更新實作計畫。

## 成功準則範例

**優良**（具體、可測試）：
- 「使用功能名稱在 Notion 中搜尋規格書頁面。」
- 「建立包含 3 個階段的實作計畫：設定 → 核心 → 精煉。」
- 「在任務資料庫中建立 5-8 個任務，屬性包含：任務（標題）、狀態、優先級、衝刺週期。」
- 「每個任務都有檢查清單格式 (- [ ] ...) 的驗收標準。」
- 「使用頁面提到標籤將任務連回規格書。」
- 「任務標題具體且具引導性（例如：'建立登入 API 端點' 而非 '認證'）。」

**拙劣**（模糊、不可測試）：
- 「建立良好的實作計畫。」
- 「任務結構良好。」
- 「適當地拆解規格書。」
- 「連結至規格書。」
