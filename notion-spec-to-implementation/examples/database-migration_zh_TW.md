# 範例：資料庫遷移實作 (Database Migration Implementation)

**使用者請求**： 「為使用者偏好設定結構綱要的資料庫遷移進行規劃與實作」

## 工作流程

### 1. 尋找與獲取規格書
```
Notion:notion-search → 找到「使用者偏好設定結構綱要遷移規格書」
Notion:notion-fetch → 擷取需求
```

**規格書摘要**： 將數據從 JSON 區塊 (JSON blob) 遷移至結構化綱要，以提升效能與數據完整性。

### 2. 解析需求
- **現狀**： 使用 JSONB 格式的 `preferences` 欄位。
- **目標**： 拆分為獨立的 `user_preferences` 與 `notification_preferences` 資料表。
- **必須維持**： 遷移期間的回溯相容性 (Backward compatibility)。
- **效能要求**： 支持 100 萬以上使用者且達成零停機 (Zero downtime) 遷移。

### 3. 建立實作計畫
```
Notion:notion-create-pages
pages: [{
  properties: {
    title: "實作計畫：使用者偏好設定遷移"
  },
  content: "[包含各階段的完整實作計畫]"
}]
```

**計畫包含內容**：
- **第一階段**： 建立帶有索引的新資料表。
- **第二階段**： 從 JSONB 進行數據回填 (Backfill)。
- **第三階段**： 雙向寫入模式 (Dual-write)（同時寫入舊欄位與新表）。
- **第四階段**： 將讀取操作切換至新結構綱要。
- **第五階段**： 移除舊的 JSONB 欄位。

### 4. 尋找任務資料庫並建立任務
```
Notion:notion-search → 找到「工程任務」資料庫
Notion:notion-fetch → 獲取結構 (任務, 狀態, 優先級, 負責人等)

Notion:notion-create-pages
parent: { data_source_id: "collection://xyz" }
pages: [
  {
    properties: {
      "任務": "撰寫遷移 SQL 腳本",
      "狀態": "待處理",
      "優先級": "高",
      "衝刺週期": "Sprint 25"
    },
    content: "## 背景 (Context)
使用者偏好設定遷移任務的一部分...

## 驗收標準
- [ ] 遷移腳本成功建立資料表
- [ ] 索引定義完成..."
  },
  // ... 其他 4 個任務
]
```

**已建立的任務**：
1. 撰寫遷移 SQL 腳本。
2. 實作數據回填任務。
3. 在 API 中加入雙向寫入邏輯。
4. 更新讀取查詢。
5. 回滾計畫與監控設定。

### 5. 追蹤進度
定期在實作計畫中更新狀態、阻礙因素與完成註記。

## 關鍵產出物

**實作計畫頁面**（已連結至規格書）。
**資料庫中的 5 個任務**（具備依賴關係與驗收標準）。
**進度追蹤紀錄**（隨著工作進展持續更新）。

## 成功因素
- 將複雜的遷移拆解為清晰的階段。
- 建立了具備具體驗收標準的任務。
- 確立了依賴順序（第一階段 → 2 → 3 → 4 → 5）。
- 採用具備回滾計畫的零停機方案。
- 將所有工作關聯回原始規格書。
