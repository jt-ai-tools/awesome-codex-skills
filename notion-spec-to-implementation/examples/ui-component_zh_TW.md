# 範例：UI 組件實作 (UI Component Implementation)

**使用者請求**： 「根據設計規格實作新的搜尋組件」

## 工作流程

### 1. 尋找規格書
```
Notion:notion-search
query: "搜尋組件設計規格"
```
找到：「全域搜尋重新設計規格 (Global Search Redesign Spec)」。

### 2. 獲取與解析規格書
```
Notion:notion-fetch
```

**需求要點**：
- 即時搜尋並具備防彈跳 (Debounced) API 呼叫。
- 鍵盤導覽（↑↓ 方向鍵, Enter, Esc）。
- 最近搜尋紀錄。
- 結果分類（頁面、人員、檔案）。
- 行動端響應式設計。
- 無障礙設計 (Accessibility)（ARIA 標籤、螢幕閱讀器）。

### 3. 建立實作計畫
```
Notion:notion-create-pages
```

**計畫階段**：
- 第一階段：基礎組件結構。
- 第二階段：API 整合與防彈跳處理。
- 第三階段：鍵盤導覽功能。
- 第四階段：最近搜尋紀錄。
- 第五階段：細節優化與無障礙設計。

### 4. 建立任務
```
Notion:notion-create-pages (共 7 個任務)
```

**任務清單**：
1. 建立 SearchInput 組件。
2. 實作 useDebounce Hook。
3. 加入鍵盤導覽邏輯。
4. 使用 LocalStorage 儲存最近搜尋紀錄。
5. 建立結果分類 UI。
6. 無障礙設計稽核。
7. 行動端響應式樣式調整。

### 5. 實作與追蹤
隨著每個任務完成，更新狀態並新增包含螢幕截圖與實作細節的進度筆記。

## 關鍵產出物

**實作計畫**（已連結至設計規格）。
**7 個組件任務**（存於工程任務資料庫中）。
**進度更新**（附帶程式碼片段與 Demo 連結）。

## 成功因素
- 清晰的組件拆解。
- 關注點分離（邏輯、UI、無障礙）。
- 每個任務都有明確的驗收標準。
- 全程參考設計規格。
- 從一開始就納入無障礙設計，而非事後補救。
- 透過視覺化的更新追蹤進度。
