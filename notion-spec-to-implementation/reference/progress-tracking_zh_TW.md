# 進度追蹤 (Progress Tracking)

## 更新頻率

### 每日更新 (Daily Updates)

針對正在進行的實作工作：

**更新內容**：
- 若狀態有變，更新任務狀態。
- 在任務中新增進度筆記。
- 更新阻礙因素。

**更新時機**：
- 工作日結束時。
- 完成重大工作後。
- 遇到阻礙因素時。

### 里程碑更新 (Milestone Updates)

當階段或里程碑完成時：

**更新內容**：
- 在計畫中將該階段標記為完成。
- 新增里程碑總結。
- 必要時更新時程表。
- 向利害關係人回報。

**更新時機**：
- 階段完成時。
- 重大交付物就緒時。
- 衝刺 (Sprint) 結束時。
- 產品發布 (Release) 時。

### 狀態變更更新 (Status Change Updates)

當任務狀態發生轉換時：

**更新內容**：
- 更新任務狀態屬性。
- 新增狀態轉換筆記。
- 通知相關人員。

**更新時機**：
- 開始工作（待處理 → 進行中）。
- 準備好審查（進行中 → 審查中）。
- 完成（審查中 → 已完成）。
- 受阻（任何狀態 → 已阻礙）。

## 進度筆記格式

### 每日進度筆記

```markdown
## 進度報告：[日期]

### 已完成
- [具體成就及其詳情]
- [具體成就及其詳情]

### 進行中
- [目前的工作項目]
- 當前狀態：[百分比或描述]

### 下一步行動
1. [下一個計畫採取的行動]
2. [下一個計畫採取的行動]

### 阻礙因素 (Blockers)
- [阻礙因素描述，以及需要誰/什麼資源來排除阻礙]
- 或：無

### 已做出的決策
- [任何技術或產品上的決策]

### 註記
[額外的背景資訊、學習心得、遇到的問題]
```

範例：

```markdown
## 進度報告：2025 年 10 月 14 日

### 已完成
- 實作使用者認證 API 端點 (login, logout, refresh)。
- 新增 JWT 權杖生成與驗證功能。
- 撰寫認證服務的單元測試（涵蓋率 95%）。

### 進行中
- 前端登入表單整合。
- 目前：表單已可提交，但需處理錯誤狀態。

### 下一步行動
1. 完成登入表單中的錯誤處理。
2. 新增載入中 (Loading) 狀態。
3. 實作「記住我」功能。

### 阻礙因素
無

### 已做出的決策
- 使用 HttpOnly Cookie 儲存 Refresh Token（比 localStorage 更安全）。
- 根據安全性審查，將環節 (Session) 逾時時間設定為 24 小時。

### 註記
- 發現了併發登入嘗試的邊緣案例，已新增至待辦清單 (Backlog)。
- 認證檢查效能良好 (<10ms)。
```

## 任務狀態追蹤

### 狀態定義

**待處理 (To Do)**：尚未開始
- 任務已準備好開始。
- 依賴關係已滿足。
- 已指派（或可供認領）。

**進行中 (In Progress)**：正積極處理中
- 工作已開始。
- 已指派給特定人員。
- 預期會有定期更新。

**已阻礙 (Blocked)**：無法繼續進行
- 依賴關係未滿足。
- 存在外部阻礙因素。
- 正在等待決策或資源。

**審查中 (In Review)**：等待審查
- 從實作者角度看，工作已完成。
- 需要進行程式碼審查 (Code Review)、QA 或核准。
- 已確定審查人員。

**已完成 (Done)**：全部完成
- 滿足所有驗收標準。
- 已通過審查與核准。
- 已部署或已交付。

### 更新任務狀態

更新時：

```
1. 更新「狀態」屬性。
2. 新增說明變更原因的進度筆記。
3. 必要時更新相關任務。
4. 透過評論通知相關人員。

範例：
屬性：{ "狀態": "進行中" }

內容更新：
## 進度報告：2025 年 10 月 14 日
開始實作。已建立基礎結構並撰寫了初步測試。
```

## 阻礙因素追蹤

### 記錄阻礙因素

遇到阻礙時：

```markdown
## 阻礙因素 (Blockers)

### [日期]：[阻礙因素描述]
**狀態**：🚧 活躍中
**影響**：[哪些項目受阻]
**排除阻礙所需**：[需要的行動/人員/決策]
**負責人**：[誰負責排除此阻礙]
**目標解決日期**：[日期或時間範圍]
```

### 排除阻礙因素

當阻礙排除後：

```markdown
## 阻礙因素 (Blockers)

### [日期]：[阻礙因素描述]
**狀態**：✅ 已於 [日期] 排除
**解法**：[如何解決的]
**影響**：[對時程或範圍的任何影響]
```

### 呈報阻礙因素

如果阻礙需要向上呈報：

```
1. 更新任務中的阻礙狀態。
2. 新增評論並標記利害關係人。
3. 在計畫中更新阻礙對整體的影響。
4. 盡可能提議緩解方案。
```

## 自動化進度追蹤

### 基於查詢的狀態

從任務資料庫生成狀態：

```
查詢任務資料庫：
SELECT 
  "狀態",
  COUNT(*) as 數量
FROM "任務資料庫-UUID"
WHERE "相關任務" 包含 '計畫頁面-ID'
GROUP BY "狀態"

生成摘要：
- 待處理：8
- 進行中：5
- 已阻礙：1
- 審查中：2
- 已完成：12

整體：已完成 44% (12/28 項任務)
```

### 時程預估計算

計算預計完成時間：

```
平均速率：每週完成 6 項任務
剩餘任務：14 項
預計完成：約 2.3 週後

與目標對比：[符合時程 / 落後 / 提前]
```

## 最佳實踐

1. **定期更新**：不要讓更新堆積。
2. **具體明確**：「完成登入功能」優於「有進展」。
3. **數據說話**：使用百分比、計數與指標。
4. **即時記錄阻礙**：遇到阻礙立即回報，不要等待。
5. **連結工作產出**：引用 PR、部署連結或展示紀錄。
6. **追蹤決策**：記錄「為什麼」這麼做，而不僅是「做了什麼」。
7. **保持誠實**：回報真實狀態，而非樂觀預期。
8. **單一事實來源**：將「實作計畫」作為唯一的權威來源 (Source of Truth)。
