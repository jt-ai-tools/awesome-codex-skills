# 範例：衝刺計畫會議準備 (Sprint Planning Meeting Prep)

**使用者請求**： 「為明天的衝刺計畫會議 (Sprint Planning) 做準備」

## 工作流程執行

### 1. 搜尋背景資訊
```
Notion:notion-search
query: "衝刺計畫" + "產品待辦清單"
teamspace_id: "engineering-team"
```

找到：
- 上次衝刺的回顧 (Retrospective) 紀錄。
- 產品待辦清單 (Product Backlog)（已排序）。
- 當前衝刺進度。
- 團隊產能 (Capacity) 筆記。

### 2. 獲取詳情
```
執行 Notion:notion-fetch (共 4 頁)
```

**關鍵背景資訊**：
- **上次衝刺**：完成了 32/35 故事點數 (91%)。
- **速率 (Velocity)**：過去 3 次衝刺穩定維持在 30-35 點。
- **團隊**：5 名工程師，下個衝刺有 1 人休特休 (PTO)（團隊產能為 80%）。
- **待辦清單首要項目**：使用者認證優化、API 效能提升、行動端響應式問題修復。

### 3. 查詢當前衝刺任務
```
Notion:notion-query-data-sources
query: "SELECT * FROM tasks WHERE Sprint = 'Sprint 24' AND Status != 'Done'"
```

共有 3 項延續任務 (Carryover items)（皆為技術債項目）。

### 4. 建立預讀文件 (內部專用)
```
Notion:notion-create-pages
title: "Sprint 25 計畫 - 預讀文件 (內部專用)"
```

**預讀文件包含內容**：
- Sprint 24 總結（速率、延續項目）。
- Sprint 25 團隊產能評估。
- 推薦的待辦清單候選項目及其故事點數。
- 技術依賴關係。
- 風險項（認證機制變更需要足夠的 QA 時間）。

### 5. 建立議程
```
Notion:notion-create-pages  
title: "Sprint 25 計畫會議 - 議程"
```

**議程**：
- 審查 Sprint 24 完成情況 (5 分鐘)。
- 討論延續項目 (5 分鐘)。
- 審查產能（目前可用點數為 28 點） (5 分鐘)。
- 挑選待辦清單項目 (30 分鐘)。
- 識別依賴關係與風險 (10 分鐘)。
- 確認團隊承諾 (Commitments) (10 分鐘)。

### 6. 連結文件
交叉連結預讀文件與議程，並引用上次回顧紀錄與待辦清單。

## 產出結果總結

**內部預讀文件**：包含團隊背景、產能評估與阻礙因素。
**外部議程**：會議結構與討論主題。
**兩者皆儲存於 Notion**，並連結至專案頁面。

## 關鍵成功因素
- 收集了衝刺歷史以掌握速率趨勢。
- 計算了現實的產能（考慮到成員特休）。
- 預先識別了延續項目。
- 預讀文件讓團隊在開會前就掌握狀況。
- 議程讓會議保持專注並精確控制時間。
