# 格式選擇指南 (Format Selection Guide)

根據您的研究需求選擇正確的輸出格式。

## 決策樹

```
是否正在比較多個選項？
  ├─ 是 → 使用「對比分析」格式
  └─ 否 ↓

是否具備時效性或是主題簡單？
  ├─ 是 → 使用「快速簡報」
  └─ 否 ↓

是否需要正式且詳盡的文件紀錄？
  ├─ 是 → 使用「綜合報告」
  └─ 否 → 使用「研究摘要」（預設值）
```

## 格式化準則 (Formatting Guidelines)

### 標題 (Headings)
- 使用 `#` 作為標題。
- 使用 `##` 作為主要章節。
- 使用 `###` 作為子章節。
- 保持標題層級的一致性。

### 列表 (Lists)
- 使用 `-` 作為無序清單。
- 使用 `1.` 作為編號清單。
- 保持清單項目的結構平行（句式對齊）。

### 強調 (Emphasis)
- 使用 `**粗體**` 標註關鍵術語與章節標籤。
- 使用 `*斜體*` 進行強調。
- 謹慎使用以達到最大視覺衝擊力。

### 引用 (Citations)
- 務必對來源頁面使用 `<mention-page url="...">頁面標題</mention-page>`。
- 在引用資訊後立即加入註記。
- 在文末的「來源」章節中彙總所有來源。

### 表格 (Tables)
- 用於結構化的數據對比。
- 為了可讀性，建議將列數保持在 3-5 列。
- 包含標頭列。
- 適當對齊內容。

### 程式碼區塊 (Code Blocks)
在包含以下內容時使用：
- 技術規格。
- 配置範例。
- 指令範例。

## 內容準則 (Content Guidelines)

### 執行摘要 (Executive Summaries)
- 以最重要的發現開頭。
- 包含 1-2 個關鍵影響。
- 確保內容獨立成篇 (Standalone)（讀者無需閱讀全文即可獲得價值）。
- 摘要目標長度為 2-3 句話，報告則為 1 個段落。

### 關鍵發現 (Key Findings)
- 以清晰的標題句開頭。
- 使用具體證據支持。
- 包含相關的數據點或語錄。
- 立即註明來源。
- 專注於具引導性的洞察 (Actionable insights)。

### 建議 (Recommendations)
- 具體且可執行。
- 解釋每項建議背後的「為什麼 (Why)」。
- 清晰地排序優先級（優先級 1, 2, 3 或 高/中/低）。
- 相關時包含實作提示。

### 來源引用
- 使用 @提到 (Mentions) 連結至原始頁面。
- 註明資訊是否過時（檢查最後編輯日期）。
- 引用時註明具體章節。
- 將相關來源歸類在一起。
